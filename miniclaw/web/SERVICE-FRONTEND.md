# 空压机售后前端

本次仅调整前端及对应测试，依据 2026-09-26 版《面试问答汇总：空压机售后与 VisaFlow》的空压机项目主线。

- `/service`：登录后的默认入口，沿用原有 AuthGuard 和 AppLayout。
- `/service-preview`：无需后端的前端预览，仅包含静态演示数据；不会读取业务接口。
- `/chat`：沿用现有真实会话；飞书绑定与运行配置仍使用原有设置。

## 已实现的前端交互

2026-09-28 调整为 Agent 工作台：首页为售后对话、当前任务、设备和故障确认卡片、执行记录。工单、设备台账、保养和处理记录作为辅助页面。界面面向售后跟进人员，客户输入以模拟飞书消息呈现。

- 复合报修与进度需求拆成独立的本地任务，只读查询先返回结果，报修停在设备确认。
- 报修按“设备确认 → 补充故障 → 核对提交”推进；确认前不会生成工单。生成后可在对话中打开工单详情，并在工单列表找到同一记录。
- 等待补充期间可发起独立查询，原报修的设备、故障字段和阶段不被覆盖。切换辅助页保留会话，切换企业开始新会话，刷新全部重置。
- 人工接手保存需求、设备和故障摘要并停止该任务推进，不会向真实人员发出通知；保养查询需先确认设备。
- 演示输入仅用少量关键词匹配。否定、条件或不支持的表达进入人工核实，不自动写入业务。没有真实语义分类、模型调用或数值置信度。
- 工单搜索、状态筛选、设备台账、保养周期、详情和记录继续可用。企业筛选只是演示筛选，不是租户鉴权。

设备型号、序列号、企业与保养项目参考 `acs-agent/acs/seed.py`；工单和事件为前端示例。所有新建与确认操作仅保存在当前组件内存，刷新后重置，不会调用真实建单、审批、派单或飞书发送接口。`DEMO-` 编号不是后端工单编号。

多任务与挂起只在前端组件内存中演示，不代表后端具备持久化或恢复能力。问答里的数值置信度、恢复/重放、自动保养调度和派单尚未接入。执行记录中的工具名用于展示拟接入的动作；本页不会调用 MCP 或业务接口，不展示虚构准确率、连接状态或成功通知。

## 运行

在 `miniclaw/web` 运行 `npm run dev`，访问 `http://localhost:5173/service-preview`。生产工作台从 `/service` 进入，仍需现有服务登录与配置。`npm run build` 检查类型并构建。

后续接入需要提供受服务端企业作用域约束的设备、工单、事件、保养查询接口及受鉴权和幂等保护的创建/确认接口。本次没有新增这些接口或变更后端。
