# 飞书报修与管理员工作台

网站首页 `/` 是售后管理员入口。客户在飞书机器人私聊中报修，管理员在网页查看客户会话、待确认任务、全企业工单和设备台账。`/experience` 是合成企业的网页报修体验，`/service-preview` 保留旧前端样例。

## 升级与登录

按 [部署指南](deployment.md) 更新源码和离线镜像包。只 `git pull` 不会更新正在运行的镜像，需要导入新包并重新创建 Web 容器。部署脚本为已有 `.env` 补充随机 `ACS_ADMIN_PASSWORD` 和 `ACS_CHANNEL_KEY`，保留数据库密码及数据卷。

在服务器仓库目录查看管理员登录密码：

```bash
sudo grep '^ACS_ADMIN_PASSWORD=' .env
```

只将等号后面的值填入网站登录框。这是工作台密码，与服务器 SSH 密码不同；不要上传、截图公开或提交到 Git。管理 Cookie 为 HttpOnly / SameSite=Strict，固定有效期 12 小时；退出即撤销。修改 `.env` 的管理密码并重新创建容器后，旧管理会话失效。

`ACS_CHANNEL_KEY` 是 32 字节随机 AES-GCM 密钥，App Secret 加密保存在 PostgreSQL，API 仅返回是否已保存。单独备份 `.env` 并限制权限；密钥丢失或随意替换后必须重新填写 App Secret。公网管理入口使用 HTTPS，或继续通过 SSH 隧道访问。

## 创建并连接机器人

1. 在 [飞书开发者后台](https://open.feishu.cn/app) 创建企业自建应用，添加机器人能力。
2. 开通单聊消息读取 `im:message.p2p_msg:readonly`、应用发消息 `im:message:send_as_bot` 权限；按企业要求完成授权和发布。
3. 打开管理台的“飞书接入”，填写 App ID 和 App Secret，勾选启用并保存。已保存的 Secret 不会返回浏览器，再次保存时留空可保留原值；更换 App ID 时必须重新填写。
4. 在飞书“事件与回调”选择长连接接收，订阅 `im.message.receive_v1`（接收消息）。接收进程在保存配置后约 5 秒启动；长连接由服务器主动发起，不需要公网 HTTP 回调地址。
5. 设置应用可用范围，确保测试用户可找到机器人，并按平台要求发布应用版本。
6. 点“验证已保存凭证”只验证应用能取得访问令牌。再用飞书账号私聊机器人发送“报修”，在“客户会话”检查收到的消息和回复发送状态。

官方参考：[Python SDK 事件接收](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/server-side-sdk/python--sdk/handle-events)、[官方 SDK 源码](https://github.com/larksuite/oapi-sdk-python)。依赖固定 `lark-oapi==1.7.4`，在独立子进程运行官方长连接客户端；网站和渠道共用同一 PostgreSQL 领域引擎。

## 绑定客户并验证报修

首次私聊会保存为“待绑定客户”，机器人提示联系管理员。管理员进入该会话，选择设备台账中的所属企业并“保存身份绑定”。客户不能通过消息指定自己的企业、内部角色或管理员权限；不同用户即使私聊同一个机器人，也分别按应用 ID 和发送者 Open ID 绑定。

使用仓库合成台账验证时，可绑定“示例企业甲”，在飞书依次发送：

```text
报修 DEMO-GR75-0001 机器异响
查工单进度
确认报修
```

第一条只产生待确认任务；查询保留原报修；明确确认后才保存工单。管理员能看到用户原文、系统回复、发送状态和待确认设备，在“全部工单”查看结果。绑定示例企业甲的用户不能报修示例企业乙的 `DEMO-GR75-0002`。变更企业绑定后，不会恢复上一个企业的待确认任务。

## 可见范围与当前限制

- 管理员可以跨企业查看本部署收到的飞书会话，以及尚在 24 小时保留期内的网页体验会话。飞书消息从启用接入后开始保存，不导入接入前的聊天历史，也不自动读取可选 Host/Pi 的历史数据库。
- 会话列表可按渠道、客户、企业或消息搜索并翻页；单会话可逐页加载更早记录。飞书消息不使用网页体验的 24 小时清理策略，需管理员自行制定备份与保留策略。
- 当前接收机器人**私聊文本**，忽略群聊、机器人自身消息与附件。没有开放可伪造客户身份的公开事件注入 API。
- 默认使用业务规则，未接入大模型。报修、进度和保养受既有规则覆盖范围限制，不能据此宣称通用自然语言理解或生产容量。
- 入站先写持久化收件箱，再异步执行业务；重复消息复用领域事件 ID。回复使用稳定发送 UUID，失败按分钟自动重试，最多 5 次，管理台显示失败。飞书平台发送 UUID 的去重时效仍受平台规则约束，不能保证跨任意时长的恰好一次投递。
- “待收发验证”表示进程已启动；“已收到消息”表示存在实际入站记录，不代表持续在线探测。凭证检查通过不等于消息权限、事件订阅和用户可用范围均已完成。
- 管理台目前提供查看、配置和客户企业绑定；人工代回复、派单、细分管理员角色及客户设备台账编辑不在本次范围。

自动测试使用合成发送者、真实 PostgreSQL 和替代发送函数验证业务/投递边界，不冒充真实飞书端到端验收。真实应用收发需使用你自己的应用凭证和飞书用户完成。
