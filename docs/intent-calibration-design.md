# 意图分数与温度校准方案

本文件是设计方案，当前版本不生成校准概率，不使用模型在文本中自报的 confidence 作写操作依据。

现有链路先读取持久化任务状态，再让 Pi 提取 repair / maintenance / progress 候选及设备、故障、工单字段，程序验证 Schema、企业作用域、字段完整性和确认条件。离线模式使用保守关键词基线，供业务契约测试使用；它不代表模型语义分类质量。

后续分类器应输出可重复计算的 logits，使用独立的训练、校准和测试数据集，避免同一会话或同一语句模板跨集合泄漏。融合输入包括模型 logits、规则命中和当前状态特征；权限与设备归属始终是硬校验，不作为可加权抵消的特征。

单意图歧义可通过 top-1 概率及 margin 分流；复合意图采用各类别独立阈值，保留多个子任务。温度缩放拟合验证集上的负对数似然，得到 sigmoid(logit / T)。阈值根据误触发写操作的成本、precision 和 recall 选择。版本记录必须包含数据集哈希、融合器版本、温度、阈值和测试集结果。

验收应同时报告 precision、recall、ECE、Brier score、复合意图召回和危险写操作误触发率。无论分数多高，创建工单仍需当前可信用户确认和服务端业务校验。当前仓库没有温度参数、训练好的融合器或校准成绩；此方案不能表述为已完成模型校准。
