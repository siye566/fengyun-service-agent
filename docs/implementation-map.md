# 简历能力与源码证据

本版本补齐的是可复现的业务原型；源码和离线测试不证明公司任职、历史上线或实际经营效果。

| 能力 | 实现与证据 | 边界 |
| --- | --- | --- |
| 状态处理→模型解析→程序校验 | `acs/service.py` 从 SQLite 读取待处理状态，接收 Pi 的结构化候选，校验 Schema、企业、设备与必填字段；`acs-tools.ts` 只从宿主上下文取用户原文、消息 ID 和作用域 | 离线 Benchmark 使用规则基线或提供的结构化候选，没有调用真实模型；模型实际解析质量需要独立测评 |
| 澄清与确认 | 字段不足进入 awaiting_details；齐全后进入 awaiting_confirmation；只有可信本轮原文为“确认报修/确认提交”才创建；查询不会替换待确认报修 | 简单报修状态机，不是通用多任务调度器；一个线程同时保留一个报修任务 |
| 上下文装配 | `acs/context.py` 固定装配规则、企业身份、任务、设备、历史工单、故障知识；设备未明确时不猜测其历史，已选定时按设备检索 | 不含向量检索；前端仍是内存演示 |
| 分段预算与审计 | 各段 UTF-8 字节上限，总上限 10,000 bytes，接近阈值告警；检索记录按预算缩减，身份和任务超限则拒绝；记录来源、摘要、SHA-256 与预算结果；当前 Pi 入口调用 | 这是售后上下文预算，不是整个模型窗口的精确 token 核算；模型会话整体压缩由现有 Runtime 负责 |
| 企业隔离与权限 | 桥接层取可信 chatJid；company_bindings 确定 company/internal，业务工具再次校验设备和工单归属，未绑定默认拒绝；重新绑定不会读取旧企业的任务 | 应用层隔离；internal 是合并内部角色，不声称财务、工程师、管理员已完成细分 RBAC |
| 业务去重与恢复 | 消息 ID 保存结果，报修任务有稳定业务键，tickets 唯一索引和事务防重复创建；待确认状态持久化，创建后回执落库前中断可恢复 | 不含消息发送 Outbox、完整 Trace Replay 或生产故障恢复承诺 |
| 售后 Benchmark | `evals/service_cases.json` 标注意图、是否澄清、允许的工具、目标状态和工单数；脚本运行真实业务代码及临时 SQLite | 离线业务契约成绩，不是模型准确率或飞书端到端通过率 |
| 分类分数与温度校准 | [设计方案](intent-calibration-design.md) | 设计状态；没有训练权重、温度参数或校准成绩 |

服务模式使用 `ACS_SERVICE_MODE=1`，本轮身份和消息标识由宿主注入。领域写操作通过统一路由提供，直接领域工具继续作为管理员 CLI/旧模式接口。宿主机或数据库管理员仍拥有管理权限，不能将此模式称为操作系统级隔离。
